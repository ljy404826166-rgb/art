# 微信小程序作品分类体系设计规格书

## 1. 文档状态

- 状态：设计已确认，待书面复核
- 日期：2026-07-19
- 目标平台：微信原生小程序
- 实施范围：分类数据治理、云数据库派生数据、分类页查询与交互
- 非目标：Web 端及其他平台适配、在线 AI 自动分类、P3 能力

本文定义作品分类页从硬编码示意标签升级为受控词表驱动分类系统的设计。系统面向小程序端，前台固定展示“流派、题材、年代”三个分类维度；原始作品数据保持不变，分类结果以可审核、可追踪、可回滚的派生数据发布。

## 2. 背景与问题

当前分类页使用硬编码标签，标签并未依据微信云数据库中的实际作品数据生成。现有作品包含十个原始字段：

```text
id, title_cn, title_en, artist, location,
year_and_place, medium, dimensions, description, tags
```

抽样 CSV 表明，`tags` 同时混合了多种语义：

- 流派：如“浮世绘”；
- 题材：如“风景”“风俗画”；
- 媒介或技法：如“锦绘”“墨绘”“素描”；
- 时期：如“江户时代”；
- 形式：如“册页”；
- 系列：如“富岳三十六景”；
- 权利状态：如“公版图像”。

因此，不能把所有原始标签直接塞入三个前台类别，也不能在小程序运行时通过字符串猜测标签含义。现有云数据库审计还显示 `tag_ids` 和受控词表尚未形成有效覆盖，已有候选标签中也存在把画家姓名误归入题材的情况。

## 3. 目标与成功标准

### 3.1 产品目标

1. 分类页展示来自云数据库的真实、已审核标签，而不是示意按钮。
2. 用户可分别选择一个流派、一个题材和一个年代，并按跨类别交集筛选作品。
3. 分类体系能持续吸收后续作品，不依赖不断修改页面代码。
4. 不确定的分类允许为空，禁止为了覆盖率虚构标签或年代。

### 3.2 数据目标

1. 原始十字段保持原值和原义，不作为批量治理脚本的覆盖目标。
2. 分类术语具有稳定 ID、明确类型、别名、审核状态和版本。
3. 每条作品—标签关系具有来源、证据、审核状态和批次信息。
4. 小程序只读取已审核、已发布的派生结果，不执行 AI 推理或数据清洗。
5. 每次批量写入可审计、可重放、可回滚。

### 3.3 首版质量门槛

- 100% 的前台可见术语均为 `reviewed` 且 `display_enabled`；
- 100% 的可见标签计数可与实际查询结果核对一致；
- 100% 的年代标签均有符合规则的日期证据；
- 多条件筛选结果严格满足 AND 关系；
- 未分类作品仍可在“全部作品”结果中出现；
- 分类覆盖率作为治理指标报告，不作为虚构分类的理由。

## 4. 方案选择

### 4.1 采用方案

采用“受控词表 + 已审核作品标签关系 + 派生查询字段 + 预计算分类目录”的轻量架构，复用项目现有 Node.js 数据治理脚本、JSONL/CSV 审核产物和微信云数据库。

OpenRefine 可作为人工清洗、聚类和别名整理的辅助工具，但不是生产运行依赖。图像或文本模型只允许生成候选项，不得直接把结果发布到小程序。

### 4.2 未采用方案

- 直接解析 `tags`：成本低但语义混杂，无法保证准确性；
- 小程序运行时聚合：查询复杂、性能和计费不可控，也无法承担审核职责；
- 部署 Label Studio、Skosmos 等大型平台：当前数据量和团队流程不需要其运维成本；
- 依靠图像模型自动定类：可作为候选来源，但不能替代受控词表和人工审核。

## 5. 总体架构与边界

```mermaid
flowchart LR
    Raw["原始 artworks 十字段"] --> Candidate["候选提取与规范化"]
    Candidate --> Review["受控词表与人工审核"]
    Review --> Links["artwork_tag_links"]
    Links --> Derived["作品派生分类字段"]
    Derived --> Catalog["category_catalog"]
    Catalog --> Miniapp["微信小程序分类页"]
    Derived --> Miniapp
```

职责边界如下：

- 原始数据层保存事实来源和原始文本；
- 治理脚本负责候选生成、别名匹配、日期解析、报告和批量写入；
- 人工审核负责术语类型、歧义关系和低置信度候选；
- 云数据库保存已审核关系以及面向小程序的派生数据；
- 小程序只负责目录展示、状态交互和结果查询。

不在小程序端进行：标签分词、术语类型推断、模型调用、跨集合实时统计或未审核数据发布。

## 6. 分类体系

### 6.1 前台三个分类维度

#### 流派 `style`

表示得到艺术史语境支持的艺术运动、画派或风格，例如印象派、后印象派、巴洛克、浮世绘。媒介、技法、年代、画家姓名、作品系列不得归入流派。

每幅作品允许 0—2 个已审核流派。没有直接证据时允许为空。

#### 题材 `subject`

表示作品“描绘什么”或所属图像题材，例如肖像、风景、海景、夜景、风俗、静物。题材可以使用 `parent_id` 建立层级，例如“海景”可隶属于“风景”，但首版筛选以具体已发布术语为单位，不自动扩大到父级或子级。

每幅作品允许 0—4 个已审核题材；目标是在证据充分时至少提供一个，但空值合法。

#### 年代 `period` + `period_kind=decade`

表示作品可由创作时间确定的十年区间，标签统一采用 `1900s`、`1930s` 等格式。前台不展示世纪、时代或王朝作为年代筛选项。

每幅作品允许 0—2 个年代标签。宽泛时期不推断为具体十年。

### 6.2 后台保留的术语类型

除三个前台维度外，受控词表继续保存以下类型，防止原始标签语义丢失：

- `medium`：媒介或材料；
- `technique`：技法；
- `period`：时期，其 `period_kind` 可为 `decade`、`century` 或 `era`；
- `format`：册页、卷轴等作品形式；
- `series`：作品系列；
- `rights`：权利状态；
- `region`：地区。

这些类型首版不进入分类页，但可被后续详情展示、搜索或治理流程复用。

## 7. 数据模型

### 7.1 `vocab_terms`

每个术语一条记录，建议字段如下：

```json
{
  "_id": "style-impressionism",
  "type": "style",
  "period_kind": "",
  "label_zh": "印象派",
  "label_en": "Impressionism",
  "aliases": ["印象主义", "Impressionist"],
  "parent_id": "",
  "review_status": "reviewed",
  "display_enabled": true,
  "sort_order": 100,
  "authority_ids": {},
  "created_at": "2026-07-19T00:00:00.000Z",
  "updated_at": "2026-07-19T00:00:00.000Z"
}
```

规则：

- `_id` 是稳定业务 ID，不随中文显示名调整而变化；
- `review_status` 只允许 `candidate`、`reviewed`、`rejected`；
- 别名在规范化后必须保持唯一归属，冲突别名不得自动匹配；
- 术语合并时保留旧 ID 到新 ID 的重定向记录，禁止静默复用旧 ID；
- 只有 `reviewed` 且 `display_enabled=true` 的前台类型术语可进入分类目录。

### 7.2 `artwork_tag_links`

每条记录表示一幅作品与一个受控术语之间的关系：

```json
{
  "_id": "link-artwork-2597-style-ukiyo-e",
  "artwork_id": "2597",
  "tag_id": "style-ukiyo-e",
  "tag_type": "style",
  "source": "raw-tag-exact-alias",
  "source_field": "tags",
  "source_text": "浮世绘",
  "evidence": "reviewed exact alias",
  "confidence": 1,
  "is_primary": true,
  "review_status": "reviewed",
  "source_batch": "classification-2026-07-19-v1",
  "reviewed_at": "2026-07-19T00:00:00.000Z"
}
```

同一 `artwork_id + tag_id` 只允许一条有效关系。关系状态允许 `candidate`、`reviewed`、`rejected`。小程序派生字段只投影 `reviewed` 关系。

`artwork_id` 必须使用作品在云数据库中的稳定业务主键，并与作品文档的 `_id` 或既有 `id` 建立唯一映射。若同一原始 `id` 对应多个文档、主键为空或映射不唯一，该作品必须进入冲突报告，不能生成关系。

### 7.3 `artworks` 派生字段

在不修改原始十字段的前提下，作品文档增加可重建的派生字段：

```json
{
  "style_ids": ["style-impressionism"],
  "subject_ids": ["subject-seascape"],
  "decade_ids": ["period-1880s"],
  "tag_ids": [
    "style-impressionism",
    "subject-seascape",
    "period-1880s"
  ],
  "category_filter_keys": [
    "style:style-impressionism",
    "subject:subject-seascape",
    "decade:period-1880s",
    "style:style-impressionism|subject:subject-seascape",
    "style:style-impressionism|decade:period-1880s",
    "subject:subject-seascape|decade:period-1880s",
    "style:style-impressionism|subject:subject-seascape|decade:period-1880s"
  ],
  "classification_version": "classification-v1",
  "filter_key_schema_version": 1,
  "classified_at": "2026-07-19T00:00:00.000Z"
}
```

这些字段不是新的事实来源，可以从 `artwork_tag_links` 重建。分类脚本不得修改标题、作者、日期、媒介、描述或原始 `tags`。

`tag_ids` 收录该作品全部已审核术语，包括暂不在前台展示的媒介、技法、时期、形式、系列、权利和地区；`style_ids`、`subject_ids`、`decade_ids` 是三个前台维度的子集。`category_filter_keys` 只由这三个前台子集生成。

### 7.4 `category_catalog`

每条记录对应一个可展示分类项：

```json
{
  "_id": "classification-v1-style-impressionism",
  "catalog_version": "classification-v1",
  "group": "style",
  "term_id": "style-impressionism",
  "label": "印象派",
  "artwork_count": 42,
  "sort_order": 100,
  "display_enabled": true,
  "publish_status": "active",
  "generated_at": "2026-07-19T00:00:00.000Z"
}
```

计数只包含 `status=published` 且关系已审核的作品。流派和题材按人工维护的 `sort_order` 排序；年代按十年倒序排列。`artwork_count=0` 的术语不在首版页面展示。

## 8. 分类生成与审核规则

### 8.1 处理优先级

候选和关系按以下证据优先级处理：

1. 已人工审核的导入映射；
2. 原始标签与已审核术语或唯一别名的精确匹配；
3. 确定性日期解析；
4. 标题、描述或作者关系生成的文本候选；
5. 图像或多模态模型候选。

第 1—3 类在满足对应规则时可自动进入 `reviewed`。第 4—5 类只能进入 `candidate`，必须人工审核后才能发布。

### 8.2 文本规范化

规范化只用于匹配，不回写原始文本。至少处理：

- Unicode、全半角和首尾空白统一；
- 中英文分隔符统一；
- 大小写和重复空白归一；
- 已审核别名映射；
- 重复标签去除；
- 冲突别名隔离并进入人工审核。

系统必须输出未识别词、跨类型冲突、疑似人名、重复词和被拒绝候选报告。

### 8.3 流派规则

- 已审核原始标签或唯一别名精确匹配可自动建立关系；
- 从画家常见风格继承到具体作品只能作为候选，因为画家可能跨多个时期或风格；
- 标题、描述和图像模型识别出的风格只能作为候选；
- 媒介、技法、地区、时代、系列和作者姓名必须被类型规则拦截；
- 超过 2 个已审核流派时进入冲突报告，不自动截断。

### 8.4 题材规则

- 已审核原始标签或唯一别名精确匹配可自动建立关系；
- 标题和描述中的题材词只生成候选，除非后续建立了经过审核的确定性映射规则；
- 图像模型只能生成候选及置信度；
- 题材描述作品内容，不接受作者、媒介、技法、时期、系列和权利状态；
- 超过 4 个已审核题材时进入冲突报告，不自动截断。

### 8.5 年代规则

年代从 `year_and_place` 中的日期证据确定，不从画家生卒年、时代标签或模型推断。

确定性规则如下：

1. 单一年份或明确的约年，例如 `1903`、`约1903年`，归入该年份所在的 `1900s`；
2. 起止年份位于同一十年，归入一个年代；
3. 起止年份跨越两个相邻十年、跨度不超过 10 年时，归入两个年代；
4. 跨越三个及以上十年、跨度超过 10 年、存在多个互相冲突的年份时，进入日期人工审核队列；
5. 只有“19世纪”“江户时代”“创作年份不详”等宽泛信息时，不生成 decade，进入日期补全队列；
6. 解析出的年份小于 1、大于执行时的当前公历年份，或起止年份倒置时必须报错，不生成年代；公元前年份首版进入日期补全队列；
7. 同一作品自动生成的 decade 不得超过 2 个。

日期解析器只接受列入测试用例的日期模式，并保留匹配到的原始片段作为证据；`year_and_place` 中无法识别为日期模式的地点数字或其他数字不得参与年代计算。

例如：`1896—1902` 生成 `1890s` 和 `1900s`；`1890—1908` 因跨度超过 10 年进入人工审核；“19世纪”不生成具体年代。

### 8.6 dry-run 产物

默认执行只生成文件和报告，不写云数据库。至少输出：

- 候选术语表；
- 自动确认关系表；
- 待人工审核关系表；
- 类型冲突与别名冲突表；
- 日期补全队列；
- 每幅作品的派生字段预览；
- 分类目录与计数预览；
- 写入 manifest 和回滚 manifest；
- 覆盖率、冲突率、空值率和来源分布统计。

只有显式 `--apply` 且 dry-run 审计通过后才能写库。

## 9. 查询索引设计

### 9.1 `category_filter_keys`

由于页面每个类别最多选择一个标签，跨类别使用 AND，系统为每幅作品预计算所有有效的单项、两项和三项组合键。键的类别顺序固定为：

```text
style -> subject -> decade
```

示例：

```text
style:style-impressionism|subject:subject-seascape|decade:period-1880s
```

查询时将当前选择规范化为一个键，再查询：

```text
status = published
AND category_filter_keys 包含目标键
```

这样避免在小程序端组合多个数组条件，也不需要运行时跨集合聚合。

组合数量有明确上限。按每幅作品最多 2 个流派、4 个题材、2 个年代计算，最多生成：

- 单项键：8 个；
- 两项键：20 个；
- 三项键：16 个；
- 总计：44 个。

超过分类数量上限的作品必须先解决冲突，不能通过截断关系来强行生成键。

### 9.2 索引与分页

实施阶段应根据当前云数据库能力建立与以下条件匹配的索引：

- `status + category_filter_keys + 稳定排序字段`；
- 无筛选时的 `status + 稳定排序字段`；
- `category_catalog` 的 `catalog_version + publish_status + group + sort_order`。

结果每页 20 条。排序必须包含稳定唯一键作为最终排序条件，确保触底加载无重复、无漏项。总数通过与结果查询相同的条件执行计数，不使用标签目录中的单项计数估算多条件结果。

## 10. 小程序分类页设计

### 10.1 目录加载

页面启动时读取当前激活版本的 `category_catalog`，只展示：

- `publish_status=active`；
- `display_enabled=true`；
- `artwork_count>0`；
- 对应术语仍为 `reviewed`。

页面不得在目录失败时恢复硬编码示意标签。可使用同一目录版本的本地缓存；没有有效缓存时显示错误状态和重试入口。

### 10.2 交互规则

- 流派、题材、年代各自最多选择一个标签；
- 点击未选标签：选中并刷新结果；
- 点击同组其他标签：替换该组选择；
- 再次点击已选标签：清除该组选择；
- 三组之间执行 AND；
- 提供“清除筛选”，一次清空所有选择；
- 无选择时展示全部已发布作品；
- 保留现有分组折叠、横向标签和作品卡片视觉结构；
- 年代按新到旧显示。

选择变化时应重置页码和结果列表，取消过期请求的状态写入，避免快速点击导致旧请求覆盖新结果。

### 10.3 页面状态

- 初始加载：显示骨架或加载态；
- 有结果：显示准确总数并支持触底追加；
- 空结果：显示“暂无符合条件的作品”，保留当前筛选并允许清除；
- 查询失败：保留选择和已有结果，显示可重试错误，不伪装成 0 条；
- 目录失败：使用同版本有效缓存，否则显示目录错误和重试；
- 离线：缓存可用时展示缓存目录和已缓存结果状态，否则提示联网重试。

只有宽泛年代信息的作品会出现在无年代筛选的结果中，但不会命中任何 decade 条件。

## 11. 数据迁移与发布

### 11.1 迁移顺序

1. 对生产云数据库执行只读审计并导出快照；
2. 从 `tags`、标题、描述和创作时间生成候选；
3. 建立并人工审核受控词表、别名和术语类型；
4. dry-run 生成关系、年代、筛选键、目录、冲突报告和日期队列；
5. 人工审核统计报告和抽样结果；
6. 分批写入 `vocab_terms`、`artwork_tag_links` 和作品派生字段；
7. 生成并核对 `category_catalog`；
8. 重新审计云数据库，核对数量、覆盖率、计数和查询结果；
9. 数据门禁通过后切换小程序分类页。

### 11.2 版本与回滚

每个批次记录：

- `classification_version`；
- `filter_key_schema_version`；
- `source_batch`；
- 脚本版本和执行时间；
- 新增、更新、跳过、冲突数量；
- 写入前值和写入后值；
- 分类目录版本。

分类目录采用版本化发布。同一时刻只能有一个 `active` 版本。若数据或页面出现严重问题，可切回上一目录版本并依据回滚 manifest 恢复派生字段；原始十字段不参与回滚，因为从未被修改。

### 11.3 分阶段上线

1. 先写入和审计词表、关系及派生字段，旧分类页保持不变；
2. 在开发和体验环境验证新版查询；
3. 数据与查询门禁通过后启用新版分类页；
4. 保留上一分类目录版本和页面切换能力，直至观察期结束；
5. 后续新增作品继续执行“候选—审核—派生—审计—发布”流程。

新增作品应在派生分类完成后才进入 `published`。已发布作品需要修改分类时，采用受控维护批次：批次开始前保留当前目录和派生字段快照，批量写入期间不激活新目录，全部写入与核对完成后才切换目录；门禁失败则依据 manifest 恢复旧派生字段。首版不支持在生产端边写边发布分类变更。

## 12. 错误处理与数据门禁

以下情况阻止发布：

- 可见术语不是 `reviewed`；
- 同一别名映射到多个有效术语；
- 关系引用不存在或已拒绝的作品/术语；
- 作品分类数量超过上限；
- decade 没有可追溯日期证据；
- 筛选键不符合固定顺序或包含未审核关系；
- 目录计数与同条件查询不一致；
- 同时存在多个激活目录版本；
- 分页抽样出现重复或漏项；
- dry-run 与 apply 影响范围不一致。

单条异常记录进入隔离报告，不应导致脚本静默跳过。批次是否继续由门禁规则决定，并在 manifest 中保留明确原因。

## 14. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 原始标签语义混杂 | 错误分类 | 受控类型、别名审核、冲突隔离 |
| 为追求覆盖率强行推断 | 数据失真 | 允许空分类，候选与发布分离 |
| 画家风格被直接继承 | 作品误归类 | 只生成候选，人工审核 |
| 宽泛时间被伪造成 decade | 年代筛选不可信 | 确定性解析和日期补全队列 |
| 运行时多条件查询复杂 | 性能不稳定 | 预计算规范化组合键 |
| 组合键膨胀 | 文档体积增加 | 分类数量上限，单幅最多 44 键 |
| 目录和作品字段版本错配 | 标签计数或结果错误 | 目录版本、schema 版本和发布门禁 |
| 批量写库污染生产数据 | 大范围错误 | 默认 dry-run、快照、manifest、分批 apply 和回滚 |
| 目录请求失败 | 页面不可用 | 同版本缓存、错误状态和重试，不使用假标签 |

## 15. 实施边界

首个实施计划应覆盖：

1. 受控词表和审核产物格式；
2. 标签与日期候选生成；
3. 关系、派生字段、筛选键和目录生成；
4. 云数据库 dry-run/apply/审计/回滚；
5. 分类服务与分类页改造；
6. 自动化测试、开发者工具和真机验收清单。

不在首个实施计划内：

- 其他平台的分类页；
- 在线管理后台；
- 自动发布 AI 分类；
- 图像或多模态模型接入；首版只保留候选来源接口和审核字段；
- 父子题材的递归筛选；
- 媒介、技法、地区、系列等新的前台筛选组；
- 与本分类需求无关的 P3 功能。
