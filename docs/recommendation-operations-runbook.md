# Masterpiece 分类与推荐体系运营手册

适用版本：

- `controlled-vocabulary-v1`
- `classification-v6`
- `recommendation-signals-v1`
- `recommendation-channels-v1`
- `recommendation-system-v1`

## 1. 数据边界

以下维度必须分开维护：

| 维度 | 字段 | 用途 |
|---|---|---|
| 严格分类 | `classification_ids` | 分类页筛选 |
| 受控元数据 | `tag_ids` | 媒介、技法、载体、系列等 |
| 画家 | `artist_ids` | 独立画家频道 |
| 宽泛推荐信号 | `recommendation_signal_ids` | 首页策展与探索 |

画家姓名不得写入普通标签词表。频道标题必须保持单一语义：

“花鸟虫兽”这类宽泛或组合语义应作为推荐信号维护，不得为了保留首页入口而同时写入多个严格题材分类。

- 画家频道只显示画家姓名。
- 分类、标签或推荐信号频道只显示对应词条名称。
- 禁止生成“画家 · 标签”形式的组合标题。

## 2. 新数据进入生产的标准流程

每次新增或修订作品后，必须依次执行：

1. 保留原始 `tag_keys`、来源文字和原始画家字段作为证据。
2. 重新生成 `classification-v6` 作品字段与关系表预演。
3. 审核未知画家、歧义标签和未映射推荐信号。
4. 重新生成推荐资格、稳定随机桶和频道目录。
5. 生成正式发布包：

   ```text
   npm run recommendation:release
   ```

6. 运行生产写入预检：

   ```text
   npm run cloudbase:recommendation:plan
   ```

7. 先写隔离试点集合：

   ```text
   npm run cloudbase:recommendation:pilot
   ```

8. 试点通过后才能使用带生产环境精确确认参数的正式部署命令。
9. 部署完成后执行：

   ```text
   npm run recommendation:audit
   npm run recommendation:smoke
   npm run recommendation:devtools-smoke
   ```

   `recommendation:audit` 校验全量数据、索引、权限和客户端契约；
   `recommendation:smoke` 对通用推荐池、画家、分类、标签和推荐信号执行真实云端查询；
   `recommendation:devtools-smoke` 在开发者工具自动化端口开启时验证首页运行与交互。

## 3. 阻断级门禁

任意一项不满足时不得继续发布：

- 发布清单与生产集合 ID 不一致。
- 已发布作品未使用当前分类、信号或随机桶版本。
- 存在关系表孤儿记录或未知词条、画家、信号引用。
- `random_bucket` 不在 `0–9999`。
- 频道记录的 `artwork_count` 与作品字段实际统计不一致。
- 任一合格画家缺少独立画家频道。
- `display_title` 与 `title` 不一致。
- 推荐查询需要的索引缺失。
- 推荐集合权限偏离既定配置。
- 首页不再使用纯频道标题，或栏目目录失去分页/降级能力。
- 自动化测试出现失败。

## 4. 首页与分类页验收

### 首页

- 每次重新进入或下拉刷新后，栏目组合允许变化。
- 同一栏目横向继续加载时，只返回该栏目维度下的作品。
- 已显示作品不会在同一横向批次中重复出现。
- 跨画家频道优先分散画家；画家频道只展示对应画家作品。
- 画家标题和作品属性标题分别显示。
- “查看更多”保留栏目查询类型和稳定 ID。

### 分类页

- 只展示固定受控目录。
- 多组选项采用严格交集查询。
- 首页宽泛推荐信号不会自动进入分类筛选。
- 返回详情页后保留筛选与分页状态。

## 5. 异常与降级

- 频道目录读取失败：回退到旧首页标签发现逻辑。
- 单一栏目读取失败：保留其他栏目，不切换整个首页到离线数据。
- 推荐池不可用：回退到已发布作品池。
- 云数据库不可用：显示错误状态与本地备用内容，不清除用户数据。
- 部署验证失败：停止继续写入，使用当次部署前备份恢复。

## 6. 建议执行频率

- 每次数据导入或词表修改后：完整执行发布预检、试点和生产审计。
- 每周：执行一次只读生产审计。
- 每次小程序版本发布前：执行全部小程序测试和开发者工具检查。
- 每个正式版本：至少完成一次 Android 与 iOS 真机验收。

## 7. 回滚资料

每次正式部署或定向修订都必须保留：

- 作品字段快照。
- 三类关系表快照。
- 词表、信号和频道快照。
- 部署报告与写后审计报告。
- 定向数据修订前的独立备份。

不得以重新运行生成器代替回滚快照。
